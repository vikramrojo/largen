The axes

Four axes. A component mentions none of them and gets all of them.

tone

attributedata-tone
inheritsyes
valuesprimary · secondary · success · info · warning · danger · neutral

Tone inherits, and that is the point rather than a convenience: <section data-tone="danger"> re-tones every component inside it with no per-child markup. A component never names a colour; it names var(--tone) and its derivations, and the theme decides what that resolves to.

variant

attributedata-variant
inheritsno
valuessolid · soft · outline · ghost

Derived from the tone, never a separate colour. It deliberately does NOT inherit: with a universal paint rule there is no marker separating a component from a bare <span>, so a subtree variant would paint every wrapper element it passed through. This axis is optional, and that is worth saying because the other three are not. The four variants are ways of applying a tone. If a component's variations are a surface treatment rather than a tone — a hairline in --line over --canvas, say — routing them through data-variant will tint the border and the label, and you will spend the afternoon fighting it. Write classes instead. Tone, size and state still apply; only this one has a premise your component can fail to meet.

size

attributedata-size
inheritsyes
valuesxs · sm · md · lg · xl

A single --scale multiplier, not a set of per-size rules. Multiply by var(--scale) where you set a size and express everything else in em, and padding follows type for free. This is why a component never needs a size variant of its own.

state

attributenone — it comes from the DOM
inheritsfrom the DOM
values:disabled · :user-invalid · :read-only · :focus-visible

State comes from the DOM and from real HTML attributes. It is not settable through the generative-UI manifest and should never be simulated with a class, because the browser already knows the answer.
