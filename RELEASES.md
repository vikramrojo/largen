# Releases

Generated from `genai/releases.json` by `largen contract`. Do not edit this file.

Every entry is checked against the bytes that version actually shipped, frozen at
`/v/<version>/`. Run `largen releases --check`.

Versioned paths are immutable. The unversioned `/largen.css` is not — it tracks the
newest build, so pin by version, by `sha256`, or by the `integrity` string in
`build.json` if you need bytes that cannot change under you.

## 0.3.1 — 2026-08-23

A probe that could report the wrong theme's numbers under the right theme's label. No CSS change: the stylesheets carry build id `b9fc348c`, the same as 0.3.0, so the only difference in the served bytes is the version in the banner. Nothing needs re-pinning for this — upgrade for the tooling.

### Added

- `emit_probe` takes `themeAttribute` and `themeClass`, for pages that theme by an attribute other than `data-theme` or by a class on `<html>` as Tailwind does. `largen probe --theme-class` and `--theme-attribute` on the command line.

### Fixed

- The probe's theme override is now held for the duration of the reading, and verified before any value is reported.
  It set the attribute and then awaited a settle, and a page that manages its own theme re-applies it in exactly that window — Astro fires astro:page-load, any deferred module can do the same. Every value then came back as the page's theme wearing the requested theme's label. It presented as a per-element inconsistency rather than a broken override, because elements whose colour does not depend on the theme still read correctly: one report had two selectors near-white under a light theme and a third correct, and the third was correct by coincidence. A MutationObserver now re-applies the override whenever the page changes it, and the probe refuses to report values if a competing theme signal on the root element contradicts what was asked for.
- Each row records the theme actually in effect when it was read, so a reading describes its own conditions instead of trusting its label.

## 0.3.0 — 2026-08-23

Two more slots, themes that no longer outrank you, and tools that answer why a rule lost.

### Breaking

- **`--leading` is now `--line-height-base`.**
  The slot-shaped name was taken by a token. `--line-height` is now a real per-component slot, and having a token beside it called `--leading` invited setting the wrong one.
  *To migrate:* Rename any `--leading` you set to `--line-height-base`. To set leading on one component, use the new `--line-height` slot instead.

### Added

- `--line-height` and `--letter-spacing` slots. Twelve paint slots become fourteen, so a component that changes its font size can say what leading it wants.
- largen declares its own layer order in one `@layer` statement, rather than leaving it to the order the blocks happen to appear in.
- `<progress>` and `<meter>` are themed.
- Every built file carries a banner with a build id, and `build.json` records sha256 and SRI for each — the version string alone never identified a build.

### Fixed

- Themes are layered.
  `themes/light.css` and `themes/dark.css` were unlayered while `src/tokens.css` was not. An unlayered theme outranks every layer, so a consumer's own overrides written inside `@layer largen.tokens` lost to it silently. Invisible in light mode, where the layered defaults were the only competition, and total in dark.
- Tone derivations apply wherever `--tone` is set, not only on `[data-tone]`.
  Setting `--tone` directly in a component's own rule left the derived `--tone-soft`, `--tone-ink` and `--tone-line` at their previous values.
- The last row of a table no longer draws a bottom border against the table's own edge.

### Tooling

- `resolve_cascade` — which declaration wins for a property on an element, and which cascade step decided it. No browser.
- `explain_slot` — whether the paint rule applies a slot or it reverts, and to what. Catches `--fg: inherit`, which reads as inheriting and does the opposite.
- `emit_probe` — a self-contained browser harness for the questions static analysis cannot reach.
- `check_layer_order` can derive load order from an entry file's `@import` graph instead of taking it on trust.
- `check_component_css` classifies each file in a batch, so pointing it at a directory containing a theme no longer reports every token as a colour literal.
- `largen cascade`, `largen slot` and `largen probe` expose the first three on the command line.
