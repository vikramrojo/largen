# largen design tokens — a DTCG JSON layer (baseline)

Status: exploratory baseline, 2026-09-20. Grounded in largen 0.5.2+0073498a
(`src/tokens.css`, `themes/*.css`, `genai/`) and one real consumer theme,
exe's `exe.theme.css` (250 lines, unlayered, light + dark + OS-preference).
DTCG format: https://www.designtokens.org/tr/drafts/format/ (draft 2025.10 —
the draft itself says "do not attempt to implement this version", which shapes
the source-of-truth decision below).

## Why

largen's component side is already machine-readable: `genai/manifest.json` is
the source and `largen gen` derives `schema.json`, `prompt.md`, `manifest.js`.
The token side — the ~60 custom properties in `src/tokens.css` that a theme is
allowed to set — has no JSON form at all. Consequences:

- A designer's Figma variables or Tokens Studio export cannot become a largen
  theme without someone hand-writing CSS.
- Nothing validates a theme. exe's theme sets 27 largen tokens and 40-odd
  project extras; whether every tone has its `-on` pair, or whether
  `--space-*` stayed in rem, is checked by eye.
- Tooling that ingests DTCG (Style Dictionary, Figma, Penpot, Supernova)
  cannot ingest largen's vocabulary.

largen's vocabulary is deliberately closed ("a theme sets these and nothing
else"), which is exactly what makes a JSON layer cheap to build and worth
building: the mapping is a fixed table, and validation is where the value is.

## Direction: round-trip, CSS stays source of truth

```
  src/tokens.css  ---- largen build ---->  dist/largen.tokens.json     (export)
  themes/dark.css ---- largen build ---->  dist/dark.tokens.json

  my.tokens.json  ---- largen theme ---->  my.theme.css                (import)
                            |
                            +--- validates against the vocabulary first

  largen verify   ---- CSS tokens == JSON tokens, or fail             (drift)
```

- **Export**: `largen build` emits `.tokens.json` for the defaults and each
  shipped theme, recorded in `dist/build.json` like every other artifact.
- **Import**: new `largen theme <file.tokens.json>` validates and emits a
  `@layer largen.tokens` stylesheet. DTCG becomes the theme interchange format.
- **Source of truth stays in CSS.** The reverse of the manifest precedent —
  deliberately, because the DTCG draft is unstable (colour object shape and
  `$root` are both recent). Flip later if the format settles.

Non-goals: slot/algebra tokens (`--bg`, `--pad`, `--tone-soft` are derived, not
themeable); `$extends`-based mode machinery; per-component tokens.

## Mapping: largen vocabulary -> DTCG

| largen (`src/tokens.css`) | DTCG `$type` | shape / note |
|---|---|---|
| `--canvas --ink --ink-muted --surface --line` | `color` | `{colorSpace:"srgb", components:[r,g,b], hex}` |
| `--primary`/`--primary-on` … x7 tones | group + `color` | group `tone.primary` with `$root` = the tone, `on` = its contrast. The pair constraint becomes structure. |
| `--hue-red` … `--hue-stone` (14) | `color` | group `hue` |
| `--shade --shade-strong` | `color` | `alpha` carries the rgba() opacity |
| `--tone --tone-contrast` | alias | `"{tone.neutral.$root}"`, `"{tone.neutral.on}"` |
| `--radius-sm/md/lg` | `dimension` | `{value, unit:"rem"}` |
| `--hairline` | `dimension` | `{value:1, unit:"px"}` |
| `--space-1 … --space-24` | `dimension` | rem, and *validated* rem (see below) |
| `--speed` | `duration` | `{value:120, unit:"ms"}` |
| `--font-ui --font-mono` | `fontFamily` | array, most-preferred first |
| `--text-base` | `dimension` | rem |
| `--line-height-base` | `number` | unitless ratio in largen; exe retypes it (see below) |
| `--weight-normal/medium/bold` | `fontWeight` | numbers; 650 is legal (1–1000) |
| `--lift-1 --lift-2` | `shadow` | composite; `color` is a reference to `{shade}` so the derivation survives |
| `color-scheme: light` | — | not a token; a property of the theme document (`$extensions`) |

Everything in largen's vocabulary has a DTCG type. Nothing needs the escape hatch.
(The consumer side does — see "What exe taught us".)

## `largen.tokens.json` — the defaults, excerpt

Values are `src/tokens.css` verbatim. Paths join with `.` in DTCG; the flatten
to `--name` is a fixed table in the generator, not a rule, because largen's
names are irregular (`--ink-muted`, `--hue-red`, `--text-base`).

```json
{
  "$description": "largen 0.5.2 default tokens. Generated by `largen build` from src/tokens.css.",
  "$extensions": {
    "dev.largen": { "version": "0.5.2", "build": "0073498a", "dtcg": "2025.10", "colorScheme": "light" }
  },

  "canvas":    { "$type": "color", "$value": { "colorSpace": "srgb", "components": [1, 1, 1], "hex": "#ffffff" }, "$description": "the page" },
  "ink":       { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.0863, 0.0941, 0.1098], "hex": "#16181c" }, "$description": "body text" },
  "ink-muted": { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.3608, 0.3882, 0.4314], "hex": "#5c636e" } },
  "surface":   { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.9569, 0.9608, 0.9686], "hex": "#f4f5f7" } },
  "line":      { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.8745, 0.8863, 0.9059], "hex": "#dfe2e7" } },

  "tone": {
    "$type": "color",
    "$description": "Semantic tones. Each pairs with the colour text takes when sitting ON it.",
    "primary": {
      "$root": { "$value": { "colorSpace": "srgb", "components": [0.1098, 0.4353, 0.8392], "hex": "#1c6fd6" } },
      "on":    { "$value": { "colorSpace": "srgb", "components": [1, 1, 1], "hex": "#ffffff" } }
    },
    "neutral": {
      "$root": { "$value": "{ink}" },
      "on":    { "$value": "{canvas}" }
    }
  },

  "default-tone": {
    "$description": "--tone / --tone-contrast: the fallback an un-toned component resolves against.",
    "$root":    { "$type": "color", "$value": "{tone.neutral.$root}" },

  "radius": {
    "$type": "dimension",
    "sm": { "$value": { "value": 0.25, "unit": "rem" } },
    "md": { "$value": { "value": 0.5,  "unit": "rem" } },

  "hairline": { "$type": "dimension", "$value": { "value": 1, "unit": "px" } },

  "space": {
    "$type": "dimension",
    "$description": "Rhythm between things, in rem on purpose: a section gap must not grow under data-size=lg.",
    "1": { "$value": { "value": 0.25, "unit": "rem" } },
    "2": { "$value": { "value": 0.5,  "unit": "rem" } },
    "4": { "$value": { "value": 1,    "unit": "rem" } },
    "24": { "$value": { "value": 6,   "unit": "rem" } }
  },

  "speed": { "$type": "duration", "$value": { "value": 120, "unit": "ms" } },

  "font": {
    "$type": "fontFamily",
    "ui":   { "$value": ["system-ui", "-apple-system", "Segoe UI", "Roboto", "sans-serif"] },
    "mono": { "$value": ["ui-monospace", "SFMono-Regular", "Menlo", "Consolas", "monospace"] }
  },
  "text-base":        { "$type": "dimension",  "$value": { "value": 1, "unit": "rem" } },
  "line-height-base": { "$type": "number",     "$value": 1.55 },
  "weight": {
    "$type": "fontWeight",
    "normal": { "$value": 400 },
    "medium": { "$value": 500 },
    "bold":   { "$value": 650 }
  },

  "shade":        { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0, 0, 0], "alpha": 0.08 } },
  "shade-strong": { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0, 0, 0], "alpha": 0.28 } },
  "lift": {
    "$type": "shadow",
    "1": { "$value": { "color": "{shade}",        "offsetX": { "value": 0, "unit": "px" }, "offsetY": { "value": 1, "unit": "px" }, "blur": { "value": 2,  "unit": "px" }, "spread": { "value": 0, "unit": "px" } } },
    "2": { "$value": { "color": "{shade-strong}", "offsetX": { "value": 0, "unit": "px" }, "offsetY": { "value": 8, "unit": "px" }, "blur": { "value": 28, "unit": "px" }, "spread": { "value": 0, "unit": "px" } } }
  }

```

Two things the JSON says that the CSS only implies: `--neutral` *is* `--ink`
(same hex, now an alias — a deliberate claim, check it's true), and `--lift-*`
depends on `--shade` (a reference, so a theme that changes `shade` moves the
shadows — which is what `themes/dark.css` relies on today).

## A theme is a document, not a mode

DTCG has no theming construct. That is fine: largen's theme model doesn't need
one. `themes/dark.css` sets eleven tokens and inherits the rest; a theme
document does the same — it is a *partial* document over the same vocabulary.

```json
{
  "$description": "largen dark theme. Mirrors themes/dark.css.",
  "$extensions": { "dev.largen": { "theme": "dark", "colorScheme": "dark", "dtcg": "2025.10" } },

  "canvas":    { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.0627, 0.0706, 0.0784], "hex": "#101214" } },
  "ink":       { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0.949, 0.9569, 0.9647], "hex": "#f2f4f6" } },
  "tone": {
    "$type": "color",
    "primary": {
      "$root": { "$value": { "colorSpace": "srgb", "components": [0.3529, 0.6627, 0.9412], "hex": "#5aa9f0" }, "$description": "lifted for legibility on a dark canvas" },
      "on":    { "$value": { "colorSpace": "srgb", "components": [0.0392, 0.0863, 0.1333], "hex": "#0a1622" }, "$description": "-on flips to dark" }
    }
  },
  "shade":        { "$type": "color", "$value": { "colorSpace": "srgb", "components": [1, 1, 1], "alpha": 0.07 } },
  "shade-strong": { "$type": "color", "$value": { "colorSpace": "srgb", "components": [0, 0, 0], "alpha": 0.6 } }
}
```

Rules that follow:

- The **defaults** document must cover the full vocabulary.
- A **theme** document may be partial, but must be a *subset* of the vocabulary
  (plus declared extras), and **if it sets a tone it must set both halves**.
  exe's dark block does exactly this — five material colours, seven complete
  tone pairs, three re-pointed extras, nothing else.
- `$extensions["dev.largen"].theme` names the `[data-theme="…"]` selector;
  `colorScheme` emits `color-scheme:`. Both overridable on the CLI.

## What exe taught us

exe's `exe.theme.css` is the only non-trivial largen theme I can read. Every
case below is a real line in that file and a real decision for `largen theme`.

**1. Project extras are the norm, not the exception.** exe adds `--font-tw`,
`--font-control`, `--text-2xs…--text-display`, `--leading-16…40`,
`--control-sm/md/lg`, `--tracking-*`, `--measure-page`, and a `--syntax-*` /
`--code-*` family. Its header says so: "sets largen token names only (plus the
exe extras …), never `--color-*`."

> Proposal: a theme document may carry any DTCG-valid token outside the
> vocabulary. The vocabulary check ignores it; the DTCG check still applies;
> the generator emits it verbatim as `--<flattened.path>`. A `$description`
> on the group ("sanctioned exe extras") is encouraged, not enforced.

**2. Some CSS values have no DTCG type.**

```css
--text-display:         clamp(2.5rem, 8vw, 5rem);  /* page title */
--syntax-comment-dark:  color-mix(in oklab, #EAE5DF 70%, #282624);
```

> Proposal: an escape hatch, and only one. `$extensions["dev.largen"].css`
> holds the raw declaration; `$value` may be a best-effort fallback or omitted.
> `largen theme` emits the raw string; other DTCG tools see the fallback.
> Reject anything else that fails to parse — a typo must not become an escape.

```json
{
  "text": {
    "display": {
      "$type": "dimension",
      "$value": { "value": 5, "unit": "rem" },
      "$description": "page title; fluid in CSS, fallback is the clamp ceiling",
      "$extensions": { "dev.largen": { "css": "clamp(2.5rem, 8vw, 5rem)" } }
    }
  }
}
```

**3. A consumer retyped a vocabulary token.**

```css
--line-height-base:   var(--leading-28);      /* overrides largen 1.55 -> body prose = 28px */
```

largen types it `number` (a ratio). exe aliases it to a rem `dimension`
(an absolute line box). Valid CSS, invalid DTCG: an alias must resolve to the
declared type.

> Proposal: `largen theme` **warns** on a `$type` mismatch against the
> vocabulary and emits anyway. This is a design decision largen should make
> explicitly — either `line-height-base` is declared as `number | dimension`
> in the vocabulary, or exe's retype is documented as off-contract.

**4. The dark block is written twice.** Once for `[data-theme="dark"]`, once
for `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`
— 22 identical declarations, drift waiting to happen.

> Proposal: one dark document, two selectors from the generator:
> `largen theme dark.tokens.json --scheme-media` emits both blocks.

**5. exe's theme is unlayered; largen's shipped themes are layered.** exe
chose unlayered so it wins regardless of link order; `themes/dark.css` was
made layered after an asymmetry bug (its own header comment tells the story).

> Proposal: default to `@layer largen.tokens { … }`, matching largen's own
> themes; `--unlayered` for consumers who want the exe behaviour. The generated
> header states which it is.

**6. Traceability lives in a separate design.md.** exe's header: "Every
token's value, provenance, and contrast note lives in ONE place: the 'Token
traceability' section of … design.md. Change a value there and here together."

> `$description` fixes this for free. `"$description": "brand-black on
> light-tan, 13.1:1"` travels with the value into Figma and back.

**7. Space stayed in rem — by discipline, not enforcement.** exe's header:
"--pad and --gap draw from largen's rem --space-* ladder; there is no exe pad
ladder." tokens.css spends twenty lines explaining why rem matters here.

> `largen theme` errors on a `space.*` dimension whose `unit` is not `rem`.
> This is the single most valuable validation in the whole layer.

**8. Zero needs a unit.** `--radius-sm: 0;` in exe. DTCG requires
`{ "value": 0, "unit": "rem" }` — unit even when zero. Generator must emit `0`
not `0rem` (both valid; the former matches what people write).

## `largen theme` — sketch

```
largen theme <file.tokens.json> [--out <file.css>] [--theme <name>]
             [--scheme-media] [--unlayered] [--strict]

  Validates, then emits a largen theme stylesheet.

  Errors (exit 1):
    - a token in the vocabulary has the wrong $type (unless --strict is off: warn)
    - a tone sets $root without on, or on without $root
    - space.* has unit other than rem
    - a reference does not resolve, or resolves in a cycle
    - $value missing and no $extensions["dev.largen"].css
    - a name contains { } . or starts with $
  Warnings:
    - vocabulary token retyped (line-height-base as dimension)
    - a vocabulary token is missing from a defaults document
    - an extra shadows a slot name (--bg, --pad, --gap, --radius …)  <- this one
      should probably be an error; slots are what tokens.css names were chosen
      to avoid colliding with
```

Output shape for the dark example above, `--scheme-media`:

```css
/* GENERATED by `largen theme dark.tokens.json --scheme-media`. Do not edit.
   largen 0.5.2 · DTCG 2025.10 · layered */
@layer largen.tokens {
  [data-theme="dark"] {
    color-scheme: dark;
    --canvas: #101214;
    --ink: #f2f4f6;
    --primary: #5aa9f0; --primary-on: #0a1622;
    --shade: rgba(255, 255, 255, 0.07);
    --shade-strong: rgba(0, 0, 0, 0.6);
  }
  @media (prefers-color-scheme: dark) {
    :root:not([data-theme="light"]) { /* same block */ }
  }
}
```

## `largen verify` — drift check

`largen verify` already lints components against the authoring contract. Add:
parse `src/tokens.css` and `themes/*.css`, parse the generated `.tokens.json`,
and fail if any name/value pair differs. This is the guard that lets CSS stay
the source of truth without the JSON going stale — the same reason
`largen gen` refuses hand-edits to `schema.json`.

## Open questions

1. **Colour representation.** The draft's colour object (`colorSpace` +
   `components` + optional `hex`) is the part most likely to change. Emit both
   `components` and `hex`; on import accept either. Pin `dtcg: "2025.10"` in
   `$extensions` so a future migration knows what it is reading.
2. **`$root` is new.** If it moves, the tone-pair shape moves. Fallback shape:
   `tone.primary.value` + `tone.primary.on`.
3. **Do `--hue-*` belong in the vocabulary or in a `hue` group that themes may
   omit?** largen's dark theme overrides all fourteen; exe sets none.
4. **Is `--neutral` really an alias of `--ink`?** Same hex in both shipped
   themes. If it is meant to track ink, say so in JSON; if it's coincidence,
   emit a literal.
5. **Should slot-name collision be an error?** tokens.css chose every name to
   avoid `--bg`, `--pad`, `--radius`; a consumer extra named `--radius` would
   silently break the paint rule.
6. **`$extends` for themes** — "dark extends light" is expressible in DTCG and
   would make partial documents self-describing. Deferred: adds a resolver,
   and the subset rule already gets the same guarantee.
